Houmi Studio — ข้อเสนอปรับปรุง UX/UIPreview เท่านั้น

เอกสารนี้เป็น ตัวอย่างเชิงภาพ (mockup) ที่ยังไม่แตะโค้ดจริงเลย ทุกอย่างในไฟล์นี้เป็น HTML/CSS แยกอิสระ เปิดดูได้โดยไม่ต้องรัน dev server ปัญหาทุกข้อที่ยกมาอ้างอิงจาก frontend/src จริงพร้อมเลขบรรทัด และตัวเลขทุกตัวมาจากการนับในโค้ดจริง

ปัญหาหลัก 1 ข้อ ที่อธิบายอาการอื่นเกือบทั้งหมด

Houmi ทำงานเป็น pipeline 8 ขั้น (detect → sort → ocr → mask → inpaint → font_judge → typeset → render) แต่ UI ไม่เคยแสดง "ตอนนี้หน้านี้อยู่ขั้นไหนแล้ว" ทำให้ผู้ใช้ต้องจำสถานะไว้ในหัวเอง ทุกอย่างที่เหลือ (ปุ่มเยอะ, ตัวอักษรเล็ก, เมนูซ้ำ) เป็นผลตามมาจากการที่ UI ไม่มี "แกนสถานะ" ให้ยึด

หลักฐาน: pipeline รับ 8 ค่า — runPipelineStep('detect'|'ocr'|'sort'|'mask'|'inpaint'|'font_judge'|'render'|'auto') ที่ App.tsx:2481 แต่ sidebar แสดงสถานะเป็น badge เดียวแบบ 2 ค่า p.status === 'processed' ? z-index ไม่มีระบบ

พบ 8 ค่า z-index แบบ arbitrary ใน Tailwind:

z-[60] z-[90] z-[100] z-[9999] z-[10000] z-[20000] z-[99999] z-[100000]

ข้อเสนอ: ใช้ 6 ชั้นมีชื่อ — base(0) → canvas-ui(10) → panel(20) → overlay(30) → modal(40) → toast(50)

🟡 Design Token Migration

  • ลบ @import url(fonts.googleapis.com...) จาก index.css
  • ลบ Silkscreen, VT323 references
  • แก้ชื่อ class: .pixel-btn-purple → .btn-secondary, .pixel-btn-magenta → .btn-accent
  • ลบ .input-glass ที่ประกาศซ้ำ — รวมเป็น 1
  • แทนที่ z-[100000] etc. → var(--z-modal)
  • แทนที่ text-[9px], text-[10px] → var(--t-badge) หรือ var(--t-label)
